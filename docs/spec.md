# Monitoaster 要件定義・初期設計書

2026年11月11日

## 1. 目的と利用シーン

Monitoasterは、画面の一区画を見張り、条件を満たした瞬間に画面全体の演出・音・通知で知らせるWindows用の常駐ツールです。

- 解決する問題: ジョブの「実行中→完了」のような地味な表示の変化に、目を凝らしていないと気付けない。
- 利用者: 業務PCで長時間ジョブを待つ個人。管理者権限がなく、インストールもできない環境を含む。
- 対象環境: Windows 10 22H2 / Windows 11(x64)。マルチモニターと拡大率の混在に対応する。
- 配布形態: 単一exeのポータブル版。インストーラーなし。exe名は Monitoaster.exe。
- 成功の基準: 別の作業をしていても検知から1秒以内に気付ける。誤検知と見逃しを設定で潰せる。

判定ロジックは Python 試作(region_watch.py の Detector クラス)の挙動を引き継いでいます。試作はリポジトリに含めず、その挙動は src/detect.rs の単体テストに書き写してあります。以後は本書とそのテストを基準とします。

## 2. 設計方針

優先順位は「安全 > 軽量 > 遊び心」とし、衝突したら上位を取ります。

1. 安全: 外部と通信しない。画面データを残さない。他のアプリに触れない。攻撃面になる機能は作らない。
2. 軽量: 見張っている間はほぼ何もしない。演出用の資源は演出中だけ確保する。
3. 遊び心: 演出は種類を多く、選べて、時々驚きがある。

演出の数と軽さのトレードオフは、構造で解消します。 演出はすべて1つのパーティクルエンジン上の「プリセット(設定データ)」として定義し、画像・動画・音声の素材ファイルを持ちません。絵も音もコードで生成するため、演出を1つ増やしてもexeはほとんど増えず、常駐時の負荷は変わりません。

画面設計の原則は次の3点です。

- 画面に標語やキャッチコピーを置かない。ラベルは名詞、数値は単位付きにする。
- しきい値は、現在値のメーターを見ながら決められるようにする。
- エラーや状態は状態欄の1行で伝え、モーダルダイアログで作業を止めない。

## 3. 機能要件: 区画指定と監視

v1は「1つの区画を、画面座標で見張る」ことに絞ります。

| ID | 要件 |
|---|---|
| F-01 | 区画指定。ボタンまたはホットキーで全モニターを薄暗くし、ドラッグで矩形を指定する。Escと右クリックで取消。カーソル付近に寸法(px)を表示する。 |
| F-02 | 指定直後に区画の枠を2秒表示する。「区画を表示」でいつでも再確認できる。 |
| F-03 | 区画は1つ。ただし設定とデータ構造は配列にして、複数区画に拡張できるようにする。 |
| F-04 | 区画を定期的に取り込む。間隔は0.2〜60秒、既定0.5秒。 |
| F-05 | 状態は「待機」「監視中」「検知済み(未確認)」「一時停止」の4つ。トレイアイコンの見た目で区別できる。 |
| F-06 | 健全性チェック。監視開始時に区画の中心にあるウィンドウを記録し、そのウィンドウが移動・最小化・終了したら一時停止して知らせる。 |
| F-07 | 画面ロック、スリープ、ディスプレイ構成の変更で一時停止する。復帰したら基準を取り直して再開する。 |
| F-08 | 検知後の動作は「停止(既定)」か「継続」。継続時は演出が終わってから基準を取り直す。 |
| F-09 | 監視開始から検知までの所要時間を計り、バナーに表示する。 |
| F-10 | 自分の演出を検知しない。オーバーレイを取り込み対象外にし、演出中は判定を休む。 |

F-06は、対象ウィンドウを動かしたせいで誤検知する事故を防ぐためのものです。別のウィンドウが区画に重なった場合は変化として拾うため、v1では利用上の注意とし、将来のウィンドウ追従モード(13章)で解消します。

## 4. 機能要件: 検知

「何をもって変化とするか」は、4つのきっかけと4つの調整値、それに自動調整で決めます。

### きっかけ

| きっかけ | 判定 | 向いている場面 |
|---|---|---|
| 変化したら | 監視開始時の画像と違う画素の割合が、しきい値以上 | ステータスの文字が切り替わる |
| 動きが止まったら | 直前のコマとの差が一度しきい値を超えたあと、しきい値未満が続く | スピナーや進捗バーが止まる |
| 指定色が現れたら | 指定色に近い画素の割合が、しきい値以上 | 完了で緑になる |
| 指定色が消えたら | 指定色が一度現れたあと、しきい値未満が続く | 実行中の色が消える |

### 調整値

| 項目 | 範囲 | 既定 | 意味 |
|---|---|---|---|
| 色の許容差 | 0〜120 | 24 | RGBのどれかの差がこの値を超えた画素を「違う」とみなす |
| 面積のしきい値 | 0.1〜100 % | 3 % | 区画のうち該当画素が占める割合 |
| 継続時間 | 0〜600 秒 | 1 秒 | 条件を満たした状態がこの時間続いたら検知 |
| 確認間隔 | 0.2〜60 秒 | 0.5 秒 | 取り込みの周期 |

判定は「継続時間 ÷ 確認間隔」を切り上げた回数だけ連続で条件を満たしたときに成立します(最低1回)。途中で一度でも外れたら数え直します。

- 回数の計算は時間をミリ秒の整数に直して行う。浮動小数のまま割ると 0.9秒÷0.3秒 が4回になるため。
- 色の許容差は「厳密に超えた」ときだけ違うとみなす。差がちょうど許容差の画素は同じ扱い。
- 指定色に近い画素とは、RGBのすべての差が許容差以内の画素。
- 最初の1コマは基準の取り込みに使い、判定しない。区画の大きさが変わったら基準を取り直す。

### 誤検知を減らす仕組み

- ライブメーター: 監視前から現在値としきい値を同じ目盛りで表示する。小さい値が見やすいよう平方根目盛りにする。
- 自動調整: 「今の状態を実行中として測る」を押すと5秒間のゆらぎを測り、面積のしきい値を「最大値×2+0.5ポイント」で提案する。適用は利用者が決める。
- 色を拾う: プレビューをクリックして指定色を取得する。
- 大きな区画の間引き: 画素数が100万を超える区画は縦横を間引いて比較する。
- 早期終了: 前回とバッファが完全一致なら差分計算を省く。

## 5. 機能要件: 演出

知らせ方は「画面演出」「音」「バナー」「トレイ通知」の4系統で、それぞれ独立にオン・オフできます。

### 画面演出のカタログ

| 演出 | 内容 | 段階 |
|---|---|---|
| クラッカー | 画面下の両隅から破裂音とともに、紙テープと紙吹雪が扇状に飛び出す | v1 |
| 紙吹雪 | 画面上端から色紙がひらひら回りながら降る | v1 |
| 花火 | 下から打ち上がり、上空で放射状に開いて尾を引きながら消える。3〜5発 | v1 |
| くす玉 | 画面上部中央の玉が割れ、垂れ幕(バナーの文言)と紙吹雪が落ちる | v1 |
| スポットライト | 画面全体を暗くし、見張っていた区画だけを照らす。どこが変わったかが分かる | v1 |
| フラッシュ | 画面全体が指定色でゆっくり明滅する | v1 |
| 縁ネオン | 画面の縁を光が一周して走る | v1 |
| 波紋 | 見張っていた区画を中心に輪が広がる | v2 |
| 風船 | 下から風船が上がっていく | v2 |
| 流れ星 | 斜めに光の筋が数本流れる | v2 |
| 紙飛行機 | 文言を書いた幕を引いた紙飛行機が画面を横切る | v2 |
| 号外テロップ | 画面下部を文言が帯状に流れる | v2 |
| 季節もの | 桜吹雪・雪・落ち葉 | v2 |
| 8ビット | ドット絵風の文字が跳ねて現れ、電子音が鳴る | v2 |

キャラクターや既存作品の意匠は使わず、すべて図形とパーティクルで描きます。

### 遊び心の仕掛け

- おまかせ: お気に入りにチェックした演出から毎回抽選する。
- 強さ3段階: 「控えめ」「ふつう」「全力」。粒子数・長さ・音量が連動する。
- レア演出: 3%の確率で金色だけのクラッカーや特大花火などの特別版になる。オフにできる。
- 季節連動: おまかせ時、月に応じて桜や雪が抽選候補に加わる(v2)。
- 戦績の表示: バナーに「本日3回目・所要12分34秒」と出す。回数はメモリ内だけで数え、保存しない。
- しつこさ: 確認するまで一定間隔で再演出し、回を追うごとに強さを一段上げる。離席から戻れば気付ける。
- ギャラリー: 演出を一覧から1つずつ試せる。

### 音・バナー・通知

- 音: 破裂音、ファンファーレ、チャイム、ドラムロール、電子音を波形合成で鳴らす。音量は3段階。利用者のWAVファイル(5MB以下)も指定できる。
- バナー: 画面上部に文言・検知時刻・所要時間を表示する。文言は利用者が編集できる。「確認するまで残す」を選べる。
- トレイ通知: Windowsの通知として1件出す。演出を見逃しても通知センターに残る。

### 演出の安全装置

| ID | 要件 |
|---|---|
| E-01 | オーバーレイは常にクリックを素通しし、フォーカスを奪わない。作業を妨げない。 |
| E-02 | 1回の演出は最長8秒。Escで即終了できる(Escのホットキー登録は演出中だけ)。演出中は他のアプリにEscが届かない(最長8秒)。 |
| E-03 | 光過敏への配慮。全画面の明滅は1秒に3回以下。「点滅を抑える」設定でフラッシュ系を無効にできる。 |
| E-04 | 空気を読む。プレゼン中や全画面アプリの使用中は、自動でバナーとトレイ通知だけにする(既定オン)。 |
| E-05 | 画面共有に映さない。オーバーレイをキャプチャ対象外にし、会議で共有中の相手には演出が見えないようにする(既定オン)。 |
| E-06 | 描画の初期化に失敗した環境では、バナー・音・トレイ通知だけで知らせる。 |

## 6. 画面と操作

起動から監視開始までを「区画を選ぶ → メーターを見る → 開始」の3操作で終えられるようにします。

- トレイ常駐: メニューは「区画を選ぶ」「監視を開始/停止」「演出を試す」「設定を開く」「終了」。アイコンの色と形で4つの状態を示す。
- メインウィンドウ: 小型の1画面。左に区画のプレビュー、ライブメーター、開始ボタン、状態欄。右に「検知」「演出」「全般」の3タブ。
- 検知タブ: きっかけ、調整値4つ、指定色、自動調整ボタン、検知後の動作。
- 演出タブ: 演出の一覧(お気に入りのチェックと「試す」ボタン)、強さ、レア演出、音、バナーの文言、しつこさ。
- 全般タブ: ホットキー、点滅を抑える、空気を読む、画面共有に映さない、バージョンとライセンス表示。
- ホットキー(変更可): 区画を選ぶ Ctrl+Alt+R、監視の切り替え Ctrl+Alt+W。登録に失敗したら状態欄に表示し、機能はボタンで使える。
- 閉じるボタン: ウィンドウを閉じてもトレイに残る。終了はトレイメニューから。
- 表示: Per-Monitor DPIに対応し、キーボードだけで全操作ができる。v1の表示言語は日本語で、文言は1か所に集約する。

## 7. セキュリティ要件

「通信しない」「残さない」「触らない」「実行しない」の4点を、仕様とCIの自動検査の両方で保証します。

| ID | 要件 | 検証方法 |
|---|---|---|
| S-01 | 外部と通信しない。ネットワークAPIを一切使わない。更新確認、利用状況の送信、クラッシュレポート送信を持たない。 | CIでexeのインポート表を検査し、ws2_32 / mswsock / winhttp / wininet / urlmon / iphlpapi / dnsapi のいずれかがあれば失敗 |
| S-02 | 管理者権限を要求しない。マニフェストは asInvoker、uiAccess は false。 | マニフェストの検査 |
| S-03 | 取り込んだ画面データはメモリ上だけで扱う。ファイル、クリップボード、ログに書かない。監視停止時に破棄する。 | コードレビュー、ファイル書き込み箇所が config モジュールだけであることの確認 |
| S-04 | 画面は読むだけ。入力の送出、キーボード・マウスのフック、他プロセスのメモリや設定へのアクセスをしない。ホットキーは RegisterHotKey だけを使う。 | 禁止API一覧(SendInput、SetWindowsHookEx、OpenProcess、WriteProcessMemory、CreateRemoteThread)の検索に加え、CIでexeのインポート表にも同じAPIがないことを検査 |
| S-05 | 外部プログラムを起動しない。「検知時にコマンドを実行」は作らない。設定ファイルの改ざんが任意コード実行に直結するため。 | 禁止API(CreateProcess、ShellExecute、WinExec)の検索に加え、CIでexeのインポート表にも同じAPIがないことを検査 |
| S-06 | 書き込み先はexeと同じフォルダーの設定ファイル1つだけ。レジストリ、AppData、スタートアップに書かない。フォルダーが書き込み不可なら、保存せずに動作を続ける。保存時の一時ファイル monitoaster.json.tmp だけは同じフォルダーに一時的に作る。 | 実機確認(Process Monitorで書き込み先を記録) |
| S-07 | 設定ファイルは信頼しない。64KB上限、型と範囲を検証し、範囲外は既定値に置き換える。未知のキーは無視する。壊れていても起動する。読み込みは64KB+1バイトで打ち切る(サイズを調べてから読む方式にしない)。文字列には長さの上限を設ける(バナーの文言は40文字)。 | 単体テスト(壊れたJSON、巨大ファイル、範囲外の値) |
| S-08 | WAVファイルは、ドライブ文字で始まるローカルの絶対パスだけを受け付ける。UNCパス(`\\` で始まるもの)とデバイスパスは拒否する。改ざんされた設定からファイルサーバーへの接続と認証情報の送出が起きるのを防ぐため(S-01)。拡張子と5MB上限を確かめ、上限付きでメモリに読み込み、RIFFヘッダーを確認してからOSの再生APIにメモリ再生で渡す。自前で解析しない。 | 単体テスト(UNCパス、相対パス、5MB超、ヘッダー不正) |
| S-09 | DLLの乗っ取りを防ぐ。静的にインポートするDLLは、リンカーの /DEPENDENTLOADFLAG:0x800 で検索先をSystem32に限定する(起動後の設定は、起動前に読み込まれるDLLに効かないため)。あわせて起動直後に SetDefaultDllDirectories で動的読み込みの検索先もSystem32に限定する。CRTを静的リンクし、システムDLLだけに依存する。 | CIでインポート表とロード構成(DependentLoadFlags=0x800)を検査、ダウンロードフォルダーに偽DLLを置いた実機確認 |
| S-10 | ビルドを硬化する。ASLR(高エントロピー)、DEP、CFGを有効にし、リリースでも整数オーバーフロー検査を有効にする。 | CIでPEヘッダーのフラグを検査 |
| S-11 | unsafe を隔離する。Win32とCOMの呼び出しは platform モジュールだけに置き、他のモジュールは unsafe を禁止する。 | コンパイラのlint設定 |
| S-12 | 依存を最小にする。直接依存は windows、serde、serde_json の3つ。Cargo.lock を固定し、追加は本書の改訂を必要とする。build-dependencies も増やさない。本体のライセンスはMIT。 | cargo-deny の許可リスト、cargo-audit |
| S-13 | 配布物を検証できるようにする。GitHub Actionsでビルドし、アクションはコミットハッシュで固定する。リリースにSHA-256とビルド来歴の証明を添える。 | リリース手順書 |
| S-14 | 多重起動を防ぐ。異常時は即座にプロセスを終了し、オーバーレイが画面に残らないようにする。 | 実機確認 |
| S-15 | ログは既定で出力しない。出す場合も画面内容、ウィンドウタイトルを含めない。 | コードレビュー |

### 利用者に伝えておく制約

- コード署名をしない間は、初回起動時にWindowsのSmartScreen警告が出ます。READMEにSHA-256の確認手順を書きます。
- 見張る区画に機密情報が映っていても、メモリ上の比較に使うだけで外に出ません。メインウィンドウのプレビューには表示されるため、画面共有中は設定画面を閉じておく運用とします。

## 8. 軽量性の目標値

目標は「exeは3MB以下、見張っている間のCPUは平均1%未満」です。数値は設計目標で、M0の技術検証で実測して確定します。

| 項目 | 目標 | 条件 |
|---|---|---|
| exeサイズ | 3MB以下(狙いは2MB) | リリースビルド、圧縮ツールなし |
| 監視中のメモリ | 25MB以下 | 区画400×200px |
| 監視中のCPU | 平均1%未満(1コア換算) | 区画400×200px、確認間隔0.5秒 |
| 待機中 | CPU・GPUともほぼ0 | タイマー以外で起床しない |
| 起動時間 | 0.3秒以内 | ウィンドウ表示まで |
| 演出の滑らかさ | 60fps | フルHD、強さ「ふつう」 |
| 粒子数の上限 | 600 | 強さ「全力」 |

実現手段は次のとおりです。

- 演出用の描画資源(Direct3Dデバイス、スワップチェーン)は演出の開始時に作り、終了時に解放する。
- 絵と音は実行時にコードで生成し、素材ファイルを埋め込まない。
- 取り込みバッファは使い回し、前回と完全一致なら差分計算を省く。
- フレーム時間が20msを超える状態が続いたら、粒子数を自動で半分にする。
- ビルド設定は opt-level="s"、LTO、codegen-units=1、strip、panic="abort"。
- UPXなどの実行ファイル圧縮は使わない。ウイルス対策ソフトの誤検知を招くため。

## 9. 技術選定とアーキテクチャ

Rustで書き、Microsoft公式の windows クレートでWin32を直接呼びます。ランタイム不要の小さな単一exeになり、メモリ安全で、依存が最小になるためです。

### 候補の比較

サイズは一般的な目安で、実測値ではありません。

| 候補 | exeサイズの目安 | 判断 |
|---|---|---|
| Rust + Win32直接 | 1〜3MB | 採用。ランタイム不要、メモリ安全、依存3つ |
| C# + .NET Framework 4.8 | 1MB未満 | 次点。OS同梱で依存ゼロだが、滑らかな透過オーバーレイにDirect2Dの相互運用が要り、常駐メモリも大きい |
| C# + .NET 8以降(自己完結) | 数十MB以上 | 不採用。軽量性に反する |
| Tauri / Electron | 数MB〜100MB超 | 不採用。WebViewへの依存と攻撃面が増える |
| Python + PyInstaller | 数十MB | 不採用。サイズ、起動時間、ウイルス対策ソフトの誤検知 |

### モジュール構成

| モジュール | 役割 | unsafe |
|---|---|---|
| app | 状態機械(待機・監視中・検知済み・一時停止)とメッセージループ | 禁止 |
| capture | 区画をBGRAバッファに取り込む | platform経由 |
| detect | 判定ロジック。純粋関数でOSに依存しない | 禁止 |
| effects | パーティクルエンジン、タイムライン、演出プリセットの定義 | 禁止 |
| render | オーバーレイウィンドウと描画 | platform経由 |
| audio | 効果音の波形合成と再生 | platform経由 |
| ui | メインウィンドウ、区画選択、トレイ、ホットキー | platform経由 |
| config | 設定の読み書きと検証 | 禁止 |
| platform | Win32とCOMの安全なラッパー。unsafeを書ける唯一の場所 | 許可 |

クレートはライブラリ(全モジュール)と実行ファイル(入口だけ)の2ターゲットで構成する。Windowsに依存するモジュールは cfg(windows) で囲み、windows クレートへの依存も cfg(windows) に限る。OS非依存のモジュールはLinux上でそのまま単体テストできる。

### 主要な設計判断

- 取り込み: スクリーンDCからGDIのBitBltで区画だけを取得する。小さな区画には十分速く、Windows.Graphics.Captureのような枠表示や許可操作が発生しない。
- オーバーレイ: モニターごとに1枚の最前面ウィンドウを作る。拡張スタイルは NOREDIRECTIONBITMAP、TRANSPARENT、LAYERED、TOPMOST、NOACTIVATE、TOOLWINDOW。描画はDirectCompositionのスワップチェーンにDirect2Dで行う。
- キャプチャ除外: オーバーレイに SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE) を設定する。F-10とE-05を同時に満たす。
- 演出の定義: 演出は「エミッター設定+タイムライン」のデータで表す。新しい演出はプリセットの追加だけで済み、描画コードに手を入れない。
- 文字: バナーやくす玉の垂れ幕はDirectWriteで描く。
- 音: 波形をメモリ上で合成し、PlaySoundのメモリ再生で鳴らす。
- 通知: Shell_NotifyIcon のバルーン通知を使う。トースト通知の登録(スタートメニューへのショートカット作成)を避けるため。
- 設定画面: ネイティブのコモンコントロールで組む。日本語入力とキーボード操作をOSに任せられ、UIライブラリの依存を増やさない。プレビューとメーターだけ自前描画にする。
- スレッド: UIスレッド、監視ワーカー(待機可能タイマー)、演出スレッド(演出中だけ存在)の3本。スレッド間はメッセージ送信だけでやり取りする。
- DPI: Per-Monitor V2 をマニフェストで宣言し、座標は物理ピクセルで統一する。
- 空気を読む判定: SHQueryUserNotificationState でプレゼン中・全画面中を判定する。
- マニフェスト: build.rs からリンカー引数(/MANIFEST:EMBED、/MANIFESTINPUT)で埋め込む。リソース埋め込み用のクレートを使わない(S-12)。

### 先に確かめる技術検証項目(M0)

- [ ] 拡大率が混在するマルチモニターで、オーバーレイが透過しクリックを素通しする
- [ ] キャプチャ除外を設定したオーバーレイが、自分のBitBltにも画面共有にも写らない
- [ ] 管理者権限で動くアプリの画面を、通常権限のままBitBltで取得できる
- [ ] 骨組みだけのリリースビルドのexeサイズとメモリ使用量
- [ ] バルーン通知のWindows 10 / 11での見え方
- [ ] リモートデスクトップ接続中や仮想マシン上で描画の初期化が通る。通らない場合E-06に落ちる
- [ ] BitBltの CAPTUREBLT フラグの有無で、自分のオーバーレイと他アプリのレイヤードウィンドウの写り方がどう変わるか
- [ ] フォーカスを奪わない設定のウィンドウ(バナー)がクリックを受け取れ、前面のアプリのフォーカスが変わらない(docs/ux.md P10 の前提)

検証に使える実機は Windows 11 の1台。Windows 10 での通知の見え方、拡大率が混在するマルチモニター、リモートデスクトップは実機で確かめられないため、結果欄に「未検証」と明記して残す。仮想マシン上での描画の初期化は、CIのWindowsランナーで参考値を取る。

## 10. 設定ファイル

設定はexeと同じフォルダーの monitoaster.json 1つに保存します。

```json
{
  "version": 1,
  "watches": [
    {
      "region": { "x": 1200, "y": 340, "w": 220, "h": 48 },
      "trigger": "change",
      "tolerance": 24,
      "area_pct": 3.0,
      "hold_sec": 1.0,
      "interval_sec": 0.5,
      "color": "#22aa44",
      "after_detect": "stop"
    }
  ],
  "effects": {
    "favorites": ["cracker", "fireworks", "kusudama"],
    "pick": "random",
    "intensity": "normal",
    "rare": true,
    "accent_color": "#ffd400",
    "sound": { "enabled": true, "kind": "fanfare", "volume": "normal", "wav_path": "" },
    "banner": { "enabled": true, "message": "ジョブ完了", "sticky": false },
    "tray_notice": true,
    "repeat": { "enabled": false, "every_sec": 10 }
  },
  "general": {
    "reduce_flash": false,
    "quiet_when_busy": true,
    "hide_from_capture": true,
    "hotkeys": { "pick_region": "Ctrl+Alt+R", "toggle_watch": "Ctrl+Alt+W" }
  }
}
```

- trigger は change / still / color_in / color_out のいずれか。pick は random / all。intensity と volume は low / normal / high。after_detect は stop / continue。
- 読み込み時にS-07の検証を行う。version が未知なら既定値で起動し、ファイルは上書きしない。
- 保存は一時ファイルに書いてから置き換える。書き込み途中の破損を防ぐ。
- 保存のタイミングは設定変更時と終了時。画面の内容に由来するデータは含めない。

## 11. テストと受け入れ基準

OSに依存しない部分は自動テストで、画面まわりはWindows実機のチェックリストで確認します。

### 自動テスト

- detect: 合成画像で次を確認する。1%の変化では検知しない。9%の変化が2回続くと検知する。許容差以下の色ずれは0%になる。「動きが止まったら」は最初から静止している画面では検知しない。「指定色が消えたら」は一度現れるまで検知しない。
- config: 壊れたJSON、64KB超、範囲外の値、未知のキーで、既定値に落ちて起動できる。
- effects: 各プリセットが8秒以内に終わり、粒子数が上限を超えず、明滅が1秒に3回以下である。
- CI(Windows): ビルド、テスト、インポート表の検査(S-01、S-09)、PEフラグの検査(S-10)、禁止APIの検索(S-04、S-05)、exeサイズの上限チェック、cargo-deny、cargo-audit。

### 実機チェックリスト

- [ ] 拡大率100%と150%の2画面構成で、選んだ区画とプレビューが一致する
- [ ] 4つのきっかけそれぞれで、実際のアプリ画面の変化を検知できる
- [ ] カーソルが点滅する入力欄を含む区画で、継続時間2秒なら誤検知しない
- [ ] 演出中も下のアプリをクリック・入力でき、フォーカスが移らない
- [ ] Escで演出が即座に消える
- [ ] 「継続」設定で、自分の演出を変化として拾わない
- [ ] 画面共有中の相手側に演出が映らない
- [ ] 全画面のスライドショー中はバナーとトレイ通知だけになる
- [ ] 画面ロックとスリープからの復帰で誤検知しない
- [ ] 監視中のウィンドウを動かすと一時停止して知らせる
- [ ] 読み取り専用フォルダーから起動できる
- [ ] タスクマネージャーでCPU・メモリが8章の目標内に収まる
- [ ] 通信が発生しない(リソースモニターで確認)

### v1の受け入れ基準

次の3点をすべて満たした時点でv1とします。

1. F-01〜F-10、E-01〜E-06、S-01〜S-15を満たす。
2. v1の画面演出7種がすべて動き、3段階の強さで見た目が変わる。
3. 実機チェックリストがすべて通る。

## 12. 開発ステップ(Claude Code向け)

5段階で進め、M1の時点で実用になります。各段階は前の段階の完了条件を満たしてから始めます。

1. M0 土台と技術検証: リポジトリ、モジュールの骨組み、CI(ビルドとセキュリティ検査一式)、マニフェスト、ビルド硬化。9章の技術検証項目を小さな実験コードで確かめる。完了条件: CIが緑で、検証結果が本書に反映されている。
2. M1 最小の実用版: 区画選択、取り込み、判定4種、ライブメーター、トレイ常駐、設定の保存。知らせ方はフラッシュ、バナー、音1種、トレイ通知。完了条件: 実際のジョブ完了を検知して気付ける。
3. M2 演出エンジン: パーティクルエンジンとプリセットの仕組み、クラッカー、紙吹雪、花火、くす玉、スポットライト、縁ネオン、効果音の合成、強さ3段階、安全装置E-01〜E-06。完了条件: v1の7種がギャラリーから試せる。
4. M3 仕上げ: おまかせ、レア演出、しつこさ、戦績表示、自動調整、健全性チェック(F-06、F-07)、ホットキー、画面の磨き込み。完了条件: v1の受け入れ基準を満たす。
5. M4 拡張: v2の演出、ウィンドウ追従モード、複数区画。

### 開発環境の前提

- Claude Codeのクラウド環境はLinuxのため、そこでは x86_64-pc-windows-gnu 向けの cargo check と、OS非依存モジュール(detect / effects / config)の単体テストまでを行う。mingwのリンカーを入れれば windows-gnu 向けにリンクでき、llvm-readobj でインポート表とPEヘッダーの検査スクリプトを試せる。
- 配布用exeはGitHub ActionsのWindowsランナー(MSVC)でビルドする。実機確認はその成果物をWindowsで動かして行う。
- 画面まわりはクラウド環境で動作確認できない。OS非依存のロジックを厚くし、platform 層を薄く保つ。
- 本書をMarkdownで書き出し、リポジトリの docs/spec.md に置く。要件ID(F / E / S)をコミットやテスト名から参照する。

## 13. スコープ外と将来候補

安全と軽量を守るため、次の機能は作りません。

- 検知時のコマンド実行、スクリプト連携
- Slack・メール・スマートフォンへの通知など、通信を伴うものすべて
- 自動更新、利用状況の収集
- スクリーンショットの保存、録画
- 文字認識(OCR)による判定
- Windows起動時の自動起動の登録

将来候補は優先順に次のとおりです。

1. ウィンドウ追従モード: 区画をウィンドウ内の相対位置で記憶し、PrintWindowでウィンドウを直接取り込む。ウィンドウを動かしても、他のウィンドウに隠れても監視できる。
2. 複数区画: 区画ごとにきっかけと演出を変える。
3. 除外マスク: 区画内の時計など、無視する部分を指定する。
4. 見た目の登録: 「完了時の見た目」を登録し、一致したら検知する。参照画像はメモリ上だけに持つ。
5. コード署名、英語表示、v2演出の追加。
