# M0 土台と技術検証: 作業手順

完了条件(spec.md 12章): **CIが緑で、技術検証の結果が spec.md に反映されている。**

M0が終わったらこのファイルは削除し、次の段階の手順に置き換えます。

## 済んでいること

- `Cargo.toml`(依存3つ、lint、リリースプロファイル)、`rust-toolchain.toml`(1.97.0 固定)
- `.cargo/config.toml` と `build.rs`(ビルド硬化)、`assets/Monitoaster.exe.manifest`
- `src/detect.rs`(判定ロジックと単体テスト17件。試作 region_watch.py の挙動を書き写したもの)
- `docs/spec.md`、`docs/ux.md`、`LICENSE`(MIT)、`.gitignore`
- 手元の確認: 標準ライブラリだけの最小exe(windows-gnu)は約260KB。インポートは KERNEL32 / ntdll / msvcrt / api-ms-win-core-synch の4つで、S-01 の禁止DLLも S-04・S-05 の禁止APIも含まない

**MSVCでのリンクはまだ一度も試していません。** `build.rs` のリンカー引数とマニフェストは、CIの最初の実行で確かめてください。

## 作業

順番に進めます。1〜4で CI を緑にし、5〜6で検証用exeを作り、7は利用者の実機確認を待ちます。

### 1. モジュールの骨組み

spec.md 9章の表のとおりにファイルを置きます。中身は役割を書いたdocコメントと、M1で埋める型の宣言だけで構いません。

| ファイル | cfg | 先頭の属性 |
|---|---|---|
| `src/detect.rs`(済)、`src/config.rs`、`src/effects.rs`、`src/text.rs`(文言) | なし | `#![forbid(unsafe_code)]` |
| `src/app.rs`、`src/capture.rs`、`src/render.rs`、`src/audio.rs`、`src/ui.rs` | `#[cfg(windows)]` | `#![forbid(unsafe_code)]` |
| `src/platform/mod.rs` | `#[cfg(windows)]` | `#![allow(unsafe_code)]` |

`src/main.rs` は、Windowsでは `monitoaster::app::run()` を呼ぶだけ、それ以外では何もしない形にします。

`platform` の最初の中身として、起動直後に呼ぶ2つを実装します。

- `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`(S-09)
- 名前付きミューテックスによる多重起動の検出(S-14)。すでに動いていたら、動いている方のウィンドウを前面に出して終了する(ux.md 4章)。前面に出す処理はM1で構いません

### 2. CI(`.github/workflows/ci.yml`)

- きっかけ: すべてのブランチへの push と pull_request。`permissions: contents: read`。
- アクションはコミットハッシュで固定します(S-13)。2026-11-11 時点のタグとハッシュ:

| アクション | タグ | ハッシュ |
|---|---|---|
| actions/checkout | v7.0.1 | `3d3c42e5aac5ba805825da76410c181273ba90b1` |
| actions/upload-artifact | v7.0.2 | `cf430e030ddbb5b0abf93d22962f4752f3646cd9` |
| actions/attest-build-provenance(リリース用、M3) | v4.2.2 | `4d101475d8b20a2381f78447822ac1eab6504dd8` |

- Rust は `rust-toolchain.toml` に従って rustup が入れます。ツールチェーン導入用のアクションは使いません。
- cargo-deny は EmbarkStudios/cargo-deny-action を使わず、`cargo install cargo-deny --locked --version 0.20.2` で入れます。アクションは Docker の中で配布バイナリをチェックサムなしで取ってくるため、ハッシュで固定しても中身が固定されません(S-13)。理由は ci.yml のコメントにも書きました。
- ジョブ:

| ジョブ | ランナー | 内容 |
|---|---|---|
| lint-test | ubuntu | `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo clippy --target x86_64-pc-windows-gnu -- -D warnings`、`cargo test --locked`、ソースの検査(3-a) |
| windows | windows | `cargo build --release --locked`、`cargo test --locked`、exeの検査(3-b)、検証用exeのヘッドレス実行(5)、SHA-256 の算出、成果物のアップロード(Monitoaster.exe、検証用exe、SHA-256) |
| supply-chain | ubuntu | cargo-deny(4)、cargo-audit(`cargo install cargo-audit --locked --version 0.23.0`) |

### 3. 検査スクリプト(`tools/`)

bash で書きます。Windows ランナーでも `shell: bash` で同じものを動かします。Linux 上で windows-gnu 向けのexeに対して試せます(手順は CLAUDE.md)。

**3-a. ソースの検査 `tools/check_source.sh`**

| 要件 | 検査 |
|---|---|
| S-11 | `unsafe` と `allow(unsafe_code)` が `src/platform/` の外にない |
| S-01 | `std::net` がない |
| S-04、S-05 | `std::process::Command` と、禁止API名(下の一覧)が `src/` にない |
| S-03、S-06 | ファイルに書くAPI(`fs::write`、`File::create`、`OpenOptions`、`fs::rename`、`fs::remove_file`、`fs::create_dir`)が `src/config.rs` の外にない |
| S-15 | `println!`、`eprintln!`、`dbg!` が `src/` にない(`src/bin/` の検証用exeは除く) |

禁止API名: `SendInput`、`keybd_event`、`mouse_event`、`SetWindowsHookEx`、`OpenProcess`、`WriteProcessMemory`、`ReadProcessMemory`、`CreateRemoteThread`、`CreateProcess`、`ShellExecute`、`WinExec`。

**3-b. exeの検査 `tools/check_exe.sh <exe> <msvc|gnu>`**

`llvm-readobj --coff-imports --file-headers --coff-load-config` の出力を調べます。

| 要件 | 検査 | gnu |
|---|---|---|
| S-01 | インポートするDLLに ws2_32 / mswsock / winhttp / wininet / urlmon / iphlpapi / dnsapi がない(大文字小文字を区別しない) | する |
| S-09 | インポートするDLLが許可リストに収まる。リストはスクリプトの先頭に置き、足すときは理由をコメントに書く。初期値: kernel32、ntdll、user32、gdi32、`api-ms-win-*`(gnu では msvcrt も)。M1以降で shell32、ole32、d3d11、dxgi、d2d1、dwrite、dcomp、winmm、comctl32、wtsapi32 などを必要に応じて足す | する |
| S-04、S-05 | インポートするシンボルに、3-a の禁止API名で始まるものがない | する |
| S-10 | DllCharacteristics に DYNAMIC_BASE、HIGH_ENTROPY_VA、NX_COMPAT がある | する |
| S-10 | DllCharacteristics に GUARD_CF がある | しない |
| S-09 | ロード構成の DependentLoadFlags が 0x800 | しない |
| S-02 | exe の中に `level="asInvoker"` と `uiAccess="false"` の文字列があり、`requireAdministrator` と `highestAvailable` がない | しない |
| 8章 | サイズが 3MB 以下 | する |

検査が実際に失敗することも確かめてください(たとえば `std::net::TcpStream` を一時的に使うと S-01 で落ちる)。確かめたらその変更は戻します。

### 4. cargo-deny(`deny.toml`)

- licenses: 許可は MIT、Apache-2.0、Unicode-3.0。`Cargo.lock` の実際のライセンスに合わせ、これ以外が要るなら理由を添えて相談する。
- bans: `Cargo.lock` に載っているクレートだけを許可リストに並べる(S-12)。知らないクレートが入ったら落ちる。
- sources: crates.io だけ。git 依存と他のレジストリは拒否。
- advisories: 既定のまま有効。

### 5. 検証用exe(`src/bin/m0_probe.rs`)

spec.md 9章の技術検証項目を確かめる小さなexeです。M0の完了時に削除します。unsafe はここにも書かず、必要なWin32呼び出しは `platform` に置きます(M1でそのまま使えるものを優先)。

- 結果はウィンドウの中に文字で表示します。ファイルには書きません。
- 利用者が1項目ずつボタンで実行し、見た結果をそのまま報告できるようにします。自動で判定できる項目は「成功 / 失敗」を表示し、目で見る項目は「何が見えれば成功か」を表示します。
- `--headless` を付けると、ウィンドウを出さずに自動判定できる項目だけを実行し、結果を標準出力に書いて終了します。CIの Windows ランナー(仮想マシン)で動かします。

| # | 項目 | 実験 | 判定 |
|---|---|---|---|
| 1 | オーバーレイの透過とクリック素通し | モニターごとに、spec.md 9章の拡張スタイルで最前面ウィンドウを作り、DirectComposition + Direct2D で半透明の図形を数秒動かす | 目視。下のアプリをクリック・入力でき、フォーカスが移らない |
| 2 | キャプチャ除外 | 1 のウィンドウに `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` を設定し、その領域を BitBlt で取り込んで図形の色が含まれるか調べる。設定なしの場合と比べる | 自動。加えて、会議アプリの画面共有に映らないことを目視 |
| 3 | CAPTUREBLT の有無 | 2 を CAPTUREBLT あり・なしで行う | 自動(4通りの結果を表で表示) |
| 4 | 管理者権限のアプリの取り込み | 前面のウィンドウの中央 100×100px を BitBlt で取り込み、全画素が同じ色でないことを調べる | 利用者が管理者権限のアプリ(タスクマネージャーなど)を前面にして実行 |
| 5 | サイズとメモリ | 起動後の作業セット(`K32GetProcessMemoryInfo`)を表示 | 自動。サイズはCIが測る |
| 6 | バルーン通知 | `Shell_NotifyIcon` でトレイアイコンを出し、題と本文のある通知を1件出す | 目視。通知センターに残るか |
| 7 | 描画の初期化 | D3D11デバイス(ハードウェア、失敗したらWARP)、DXGIスワップチェーン(composition用)、DirectCompositionデバイス、Direct2Dデバイスコンテキストを順に作り、どこまで通ったかを表示 | 自動。ヘッドレスでも実行 |
| 8 | フォーカスを奪わないバナー | `WS_EX_NOACTIVATE | WS_EX_TOPMOST | WS_EX_TOOLWINDOW` の小さなウィンドウを出し、クリックを受け取ったら色を変える。クリックの前後で `GetForegroundWindow` が変わらないことを調べる | 自動+目視 |

1・2・7 は、うまく行かなかった場合の代替(たとえば `WS_EX_LAYERED` の有無、`SetLayeredWindowAttributes` の要否)を試せるよう、設定を切り替えて再実行できると検証が1往復で済みます。

### 6. README.md

仮の内容を書き直します。短く保ちます。

- 何をするツールか(2〜3行)、開発中であること
- 安全に関する方針(通信しない、残さない、触らない、実行しない)。詳細は spec.md 7章へ
- ビルドとテストの手順
- 利用者向けの注意の置き場所(M3で埋める): SmartScreen と SHA-256 の確認手順、Windows 11 でトレイアイコンをタスクバーに出す手順

### 7. 実機確認と反映

1. CIの成果物(検証用exe)を、利用者が Windows 11 の実機で動かす。手順を利用者に伝える(成果物の場所、各項目で何をして何を報告するか)。
2. 結果を spec.md 9章のチェックリストの下に表(項目、結果、環境、日付)で書く。実機がない項目(Windows 10 の通知、拡大率の混在、リモートデスクトップ)は「未検証」と書く。
3. 8章の目標値の表に、実測値(exeサイズ、メモリ)の列を足す。
4. 結果が設計と食い違ったら、9章の設計判断を直し、14章の改訂履歴に残す。直し方が複数あって影響が大きいもの(オーバーレイの方式変更など)は、利用者に相談する。
5. 検証用exeと、このファイルを削除する。

## 実機確認の手順(利用者向け)

作業7の1で、利用者に Windows 11 の実機で行ってもらう手順です。30分ほどかかります。

### 準備

1. GitHub のリポジトリの「Actions」→「CI」を開き、確かめるコミットの実行(緑)を選びます。下の「Artifacts」にある `Monitoaster-M0-windows-x64-<コミットの先頭7桁>` を取ってきます(GitHub へのログインが要ります)。
2. zip を展開します。中身は `Monitoaster.exe`、`m0_probe.exe`、`SHA256SUMS.txt`、`probe.txt`(CI の仮想マシンでの結果)です。
3. 展開したフォルダーで PowerShell を開き、次を実行して、表示された値が `SHA256SUMS.txt` と一致することを確かめます。

   ```powershell
   Get-FileHash .\Monitoaster.exe, .\m0_probe.exe -Algorithm SHA256
   ```

4. メモ帳を1つ開いておきます(項目1、8で使います)。

### Monitoaster.exe(骨組み)

1. ダブルクリックします。SmartScreen の画面が出たら「詳細情報」→「実行」を押します。
2. 「Monitoaster」という題の、中身が空のウィンドウが出ます。
3. もう一度ダブルクリックしても、2つ目のウィンドウが出ないことを確かめます(多重起動の検出、S-14)。
4. タスクマネージャーの「詳細」タブで Monitoaster.exe の「メモリ(アクティブなプライベート ワーキング セット)」を見て、値を控えます。
5. ウィンドウを閉じます。

### m0_probe.exe(検証用)

ダブルクリックで起動します。黒い窓が一瞬出て消えるのは正常です。左に項目のボタン、右に結果欄があります。最初に結果欄に出る「押す前の準備」を読んでから、上から順に押してください。

| 項目 | 押す前にしておくこと | 押したあとにすること | 報告してほしいこと |
|---|---|---|---|
| 1 | メモ帳を主モニターに開いておく | 5秒の間に、オーバーレイの上からメモ帳をクリックして文字を打つ | 全モニターに枠と図形が見えたか、クリックと文字がメモ帳に届いたか、メモ帳のタイトルバーが前面の色のままだったか |
| 2・3 | なし | 約1秒待つ | 結果欄の表(結果欄を写せば足ります) |
| 2 の共有 | 会議アプリ(Teams、Zoom など)で画面全体の共有を始めておく | 30秒の間、共有された側(相手の画面か共有のプレビュー)を見る | 会議アプリの名前、自分の画面にマゼンタの四角が見えたか、共有された側に写ったか(黒い四角が写った場合はそれも) |
| 4 | 管理者として実行したメモ帳、またはタスクマネージャーを開いておく | 5秒以内にそのアプリをクリックして前面にし、待つ | アプリの名前、管理者権限だったか(タスクマネージャーの「詳細」タブの「管理者特権」列) |
| 5 | なし | なし | 結果欄の値 |
| 6 | なし | 画面右下の通知を見る。Win+N で通知センターも見る | 通知の見た目(スクリーンショットがあると助かります)、表示されたアプリ名、通知センターに残るか、m0_probe を閉じたあとも残るか、トレイにアイコンが出たか、「応答不可」がオンかオフか |
| 7 | なし | 押したあと、左下の「D3D は WARP だけを使う」にチェックを入れてもう一度押し、チェックを外す | 結果欄の表 |
| 8 | メモ帳を開いておく | メモ帳をクリックして前面にし、画面上部の青い小窓をクリックして、そのまま文字を打つ | 文字がメモ帳に入ったか、小窓の色が変わったか |

項目1または2・3で、オーバーレイが見えない、クリックが通らないなどの問題が出たときは、左下のチェックボックスで設定を変えて、もう一度試してください。試した設定ごとの結果を報告に含めてください。

### 報告

1. 「結果をすべて選択」を押し、Ctrl+C で写して、報告に貼ります。
2. 次を添えます。
   - Windows のバージョン(Win+R で `winver`)
   - モニターの台数と、それぞれの拡大率(設定 → システム → ディスプレイ)
   - GPU の種類(結果欄の項目7の「アダプター」に出ます)
   - Monitoaster.exe のメモリの値
   - 項目1、2 の共有、6、8 で見たこと
3. 確かめられない項目(Windows 10、拡大率の混在、リモートデスクトップ、会議アプリがない場合の 2 の共有)は「未検証」と書きます。
