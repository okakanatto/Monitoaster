# Monitoaster ユースケースとUI/UX設計

2026-11-11

docs/spec.md(要件)を、利用者の操作の流れに落としたものです。画面・文言・状態・時間の決まりはここを基準に実装します。spec.md と食い違う箇所は14章に「変更提案」としてまとめ、採否が決まったら spec.md に反映します。

用語は次の5つに統一します。画面でも同じ語を使います。

| 語 | 意味 |
|---|---|
| 区画 | 見張る矩形 |
| 監視 | 区画を定期的に取り込んで判定すること |
| きっかけ | 4種類の検知条件 |
| 検知 | きっかけが成立したこと |
| 演出 | 検知を知らせる画面効果・音・バナー・トレイ通知の総称 |

## 1. 利用者と場面

業務PCで数分〜数時間のジョブ(ビルド、バッチ、データ取り込み、ファイルコピー、ブラウザ上のCI)を待つ個人です。待つ間は別のウィンドウや別のモニターで作業するか、席を外します。

この種のツールが使われなくなる原因は、経験的に次の6つです。設計はこの6つを潰すことを目的にします。

| # | 困りごと | 対処(章) |
|---|---|---|
| 1 | 開始し忘れる。区画を選んだだけで安心してしまう | 選んだらすぐ監視を始める(4, 5) |
| 2 | 正しい場所を見張れているか分からない | 開始・停止のたびに区画の枠を見せる(5) |
| 3 | 誤検知する。原因が分からないので直せない | メーター、継続の進み具合、差分の強調表示、自動調整(6, 9) |
| 4 | 席を外している間に終わり、気付かない | ロックをまたいで検知する、確認するまで残す(7, 8) |
| 5 | ウィンドウを少し動かしただけで壊れる | 最小化からの復元は自動再開、移動には追従(8) |
| 6 | 会議や発表の最中に派手に鳴る | 控えめな知らせ方に自動で切り替える(7) |

## 2. ユースケース

| ID | 場面 | 頻度 | 成功の姿 |
|---|---|---|---|
| UC-1 | 今走らせたジョブを1回だけ見張る | 最多 | ホットキー → ドラッグの2操作で監視が始まり、完了の1秒以内に気付く |
| UC-2 | 毎日同じ場所のジョブを見張る | 多 | ホットキー1回で開始。枠が出るので場所が合っているか一目で分かる |
| UC-3 | 繰り返し起きる出来事を見張り続ける | 中 | 検知のたびに知らせ、放っておいても監視が続く |
| UC-4 | 席を外している間に終わる | 多 | 戻ってロックを解いた直後に知らせる。いつ終わったかが分かる |
| UC-5 | 誤検知・見逃しを直す | 初回と不調時 | 何が数えられているかを見て、1〜2項目の調整で直る |
| UC-6 | 会議・発表の最中に終わる | 少 | 画面演出と音は出ず、控えめに知らせる。あとで気付ける |
| UC-7 | 見張り先のウィンドウが動いた・消えた | 中 | 誤検知せず一時停止する。戻せば自動で再開する |

### UC-1 の流れ(基準となる体験)

1. ジョブを実行する。
2. Ctrl+Alt+R を押す。全モニターが薄暗くなる。
3. 「実行中」と出ている場所をドラッグする。
4. 離した瞬間に区画の枠と「監視を開始 ・ 変化したら」の札が2秒出る。トレイが監視中の見た目になる。フォーカスは元のアプリに戻る。
5. 別の作業をする。
6. 表示が「完了」に変わる。1秒後(継続時間)に音・画面演出・バナーが同時に出る。
7. バナーをクリックするか Esc を押す。確認済みになり、待機に戻る。

メインウィンドウを一度も開かずに終わります。初回だけは、ウィンドウを開いてメーターを見ながら調整する流れ(UC-5)になります。

### UC-4 の流れ

1. 監視を始めて席を外す。数分後にPCが自動でロックされる。取り込みを休むが、基準の画像は保つ。
2. ロック中にジョブが終わる。
3. 戻ってロックを解く。2秒待ってから取り込みを再開し、ロック前の基準と比べる。
4. 変化が継続時間だけ続いたら検知する。バナーには検知時刻を出す。

ロック中は画面を取り込めないため、検知時刻は「ロックを解いた時刻」になります。所要時間の後ろに「(ロック中に変化)」と添えます。

## 3. 状態

状態は4つです。どの状態でも、トレイアイコン・主ボタン・状態欄が同じことを示します。

| 状態 | トレイアイコン | 主ボタン | Ctrl+Alt+W | 取り込み |
|---|---|---|---|---|
| 待機 | 灰色、輪郭だけ | 監視を開始(区画がなければ「区画を選ぶ」) | 開始。区画がなければ区画選択に入る | ウィンドウを表示している間だけ |
| 監視中 | 緑、塗りつぶし+中央の点 | 監視を停止 | 停止 | する |
| 検知済み(未確認) | 金色、星形 | 確認 | 確認 | 下の表 |
| 一時停止 | 橙色、縦2本線 | 再開 / 停止(2つ並べる) | 再開 | しない |

- アイコンは色だけでなく形でも区別できるようにします。16pxで見分けられ、明るいタスクバーでも暗いタスクバーでも見えることが条件です。絵はコードで描きます。
- 待機中にウィンドウを閉じていれば、取り込みもタイマーも止めます(8章の目標「待機中はほぼ0」)。

### 検知したあとの動き

| 検知後 | 確認するまで繰り返す | 動き |
|---|---|---|
| 停止 | オフ | 検知済みに入り、確認するまで留まる。演出は1回。確認で待機へ |
| 停止 | オン | 検知済みに入り、一定間隔で再演出する。確認で待機へ |
| 継続 | オフ | 演出が終わったら自動で監視中に戻り、基準を取り直す |
| 継続 | オン | 検知済みに留まり再演出する。確認で監視中に戻り、基準を取り直す |

「確認」になる操作は、バナーのクリック、演出中の Esc、トレイアイコンのクリック、メインウィンドウを開く、主ボタン、Ctrl+Alt+W です。どれも「見た」という意思表示として扱います。

## 4. 操作の入口

### トレイ

- 左クリック: メインウィンドウを開く(開いていれば前面に出す)。検知済みなら確認も兼ねる。
- 右クリック: メニュー。

```
監視を開始        Ctrl+Alt+W     ← 状態で「監視を停止」「確認」「再開」に変わる。太字
区画を選ぶ        Ctrl+Alt+R
区画を表示
演出を試す
────────────
設定を開く
終了
```

- ツールチップ: `Monitoaster - 監視中 12分34秒 ・ 変化したら`。検知済みなら `Monitoaster - 14:32 に検知`。
- Windows 11 では新しいトレイアイコンが「隠れているインジケーター」に入ります。状態が見えるよう、タスクバーに出す手順を README に書きます。アイコンが隠れていても困らないよう、開始・停止・一時停止は必ず区画の枠でも知らせます(5章)。

### ホットキー

| キー | 動き |
|---|---|
| Ctrl+Alt+R | 区画選択に入る。選択中にもう一度押すと取り消す |
| Ctrl+Alt+W | 3章の表のとおり |
| Esc | 演出中だけ有効。演出を消して確認済みにする |

ウィンドウを閉じた状態でホットキーを使ったときは、結果を区画の枠と札で返します(「監視を開始」「監視を停止」「再開できません ・ ウィンドウが見つかりません」)。

### 起動と終了

- 起動するとメインウィンドウを表示します。区画が未指定なら主ボタンは「区画を選ぶ」です。
- すでに動いているときにもう一度exeを起動したら、動いている方のウィンドウを前面に出して、後から起動した方は終了します。
- 閉じるボタンと Esc はウィンドウを隠すだけです。その回の起動で最初に隠したときだけ、トレイ通知「トレイに常駐しています。終了はトレイのメニューから」を出します。
- 「終了」は確認なしですぐ終わります。

## 5. 区画の選択

### 画面

- 全モニターを黒35%で覆い、カーソルを十字にします。
- 案内は、カーソルがあるモニターの上部中央に1行で出します。離したあと何が起きるかを書きます。
  - ホットキー・トレイから入った場合: `ドラッグで区画を選ぶ ・ 離すと監視を開始 ・ Esc で取消`
  - メインウィンドウのボタンから入った場合: `ドラッグで区画を選ぶ ・ Esc で取消`
- ドラッグ中は、選んでいる矩形だけ覆いを抜いて元の明るさで見せ、白い1pxの枠を付けます。
- カーソルの右下に寸法の札 `220 × 48 px` を出します。画面の端では反対側に回します。
- 今の区画があれば、破線で薄く示します。

### 操作

- 8×8px 未満で離した場合はクリックとみなし、選択を続けます(取り消しにはしません)。
- Esc と右クリックで取り消します。選択に入る前の状態(監視中なら監視中)へそのまま戻ります。誤ってホットキーを押しても監視は失われません。
- キーボードだけでも選べます。矢印キーで1px(Shift で10px)動かし、Space で始点を決め、矢印で広げ、Enter で確定します。
- 区画は複数のモニターにまたがっても構いません。

### 選んだあと

1. 覆いを消し、選択前に前面にあったウィンドウへフォーカスを戻します。
2. 区画の**外側**に枠を2秒出します(F-02)。枠は区画の画素に重ねません。
3. 0.3秒待ってから基準を取り込みます。フォーカスが戻る前は、タイトルバーや選択行の色が違うためです。
4. ホットキー・トレイから入った場合は監視を始め、枠に札「監視を開始 ・ 変化したら」を付けます。メインウィンドウから入った場合は、ウィンドウを再表示して待機のままにします(メーターを見て調整するため)。

「ホットキー・トレイから選んだらすぐ監視を始める」は全般タブでオフにできます。既定はオンです。

## 6. メインウィンドウ

サイズ固定の1画面です。左は「今どう見えているか」、右は「設定」、下は「状態」です。

```
┌ Monitoaster ──────────────────────────────────────────────── ─ × ┐
│ ┌────────────────────────┐   [検知] [演出] [音と通知] [全般]      │
│ │                        │  ┌──────────────────────────────────┐ │
│ │    区画のプレビュー       │  │ きっかけ      [変化したら      ▾] │ │
│ │      300 × 170         │  │   (きっかけの説明 1行)            │ │
│ └────────────────────────┘  │ 指定色        [■]                │ │
│ □ 数えている画素を強調        │ 色の許容差     ───●──────  24     │ │
│ ▓▓▓▓▓▓░░░░░▼░░░░░░░░░░░░    │ 面積のしきい値  [  3.0 ] %        │ │
│ 変化した面積 1.2% / しきい値 3.0% │ 継続時間     [  1.0 ] 秒        │ │
│ 継続 0.0 / 1.0 秒            │ 確認間隔      [  0.5 ] 秒        │ │
│                             │ [今の状態を実行中として測る]       │ │
│ [区画を選ぶ]  [区画を表示]     │ 検知後        (•)停止  ( )継続   │ │
│ [       監視を開始        ]  └──────────────────────────────────┘ │
├──────────────────────────────────────────────────────────────────┤
│ 待機 ・ 区画 220 × 48 px                                          │
└──────────────────────────────────────────────────────────────────┘
```

### 左の列

- **プレビュー**: 区画を縦横比を保って収めます。拡大時は補間しません(画素が見えるように)。区画が未指定のときは、枠の中に `区画を選ぶと、ここに表示されます` とだけ出します。きっかけが指定色のときは、クリックでその画素の色を拾います(カーソルをスポイトに変える)。
- **数えている画素を強調**: オンにすると、判定で数えられている画素をマゼンタで塗ります。点滅するカーソルや時計が誤検知の原因だと、見て分かります。
- **メーター**: 平方根目盛り。現在値の棒、しきい値の目印(▼と縦線)、直近10秒の最大値の細い線を描きます。
  - 棒の色は「しきい値を超えたか」ではなく「きっかけの条件を満たしているか」で変えます(満たしていれば強調色、いなければ灰青)。「動きが止まったら」「指定色が消えたら」は、しきい値を**下回る**と成立するためです。
  - しきい値の目印はドラッグで動かせます。面積のしきい値の入力欄と連動します。
- **読み取り値(2行)**:
  - 1行目 `変化した面積 1.2% / しきい値 3.0%`(指定色のきっかけでは `指定色の面積`)
  - 2行目 `継続 0.5 / 1.0 秒`。あとどれだけで検知するかが分かります。「動きが止まったら」「指定色が消えたら」でまだ一度も成立側を見ていないときは `まだ動きを見ていません` / `まだ指定色が現れていません` と出します。検知しない理由が分かります。
- **主ボタン**: 3章の表のとおり。ウィンドウの既定ボタン(Enter)です。

待機中のメーターは、区画を選んだ時点(またはきっかけを変えた時点)の画像を仮の基準にして動かします。

### 検知タブ

上の図のとおりです。

- きっかけの下に説明を1行出します(11章の文言)。
- 指定色の行は、きっかけが指定色のときだけ有効にします。
- 設定の変更は監視中でもすぐ反映します。きっかけを変えたときだけ基準を取り直します。
- 自動調整は9章。

### 演出タブ

```
画面演出
┌────────────────────────────┐
│ ☑ クラッカー                │  [試す]
│ ☑ 紙吹雪                   │
│ ☑ 花火                     │  選び方  (•)おまかせ ( )すべて
│ ☑ くす玉                   │  強さ    ( )控えめ (•)ふつう ( )全力
│ ☐ スポットライト            │  演出の色 [■]
│ ☐ フラッシュ               │  ☑ レア演出
│ ☐ 縁ネオン                 │
└────────────────────────────┘
```

- チェックは「お気に入り」です。「おまかせ」はチェックした中から毎回1つ、「すべて」はチェックした全部を同時に出します。
- 「試す」は選んでいる行の演出を、今の強さで1回出します。行のダブルクリックでも同じです。Space でチェックを切り替えます。
- 1つもチェックがないときは画面演出なし(音・バナー・通知だけ)です。

### 音と通知タブ

```
音        ☑ 鳴らす   種類 [ファンファーレ ▾]   音量 ( )小 (•)中 ( )大   [試聴]
          WAVファイル [                          ] [選ぶ]
バナー    ☑ 表示する  文言 [ジョブ完了            ]   ☐ 確認するまで残す
トレイ通知 ☑ 出す
繰り返し  ☐ 確認するまで繰り返す   間隔 [ 30 ] 秒
```

- WAVの欄は種類が「WAVファイル」のときだけ有効にします。受け付けられないファイル(S-08)は、欄の下と状態欄に理由を出します。
- 文言は40文字まで。空欄なら「検知しました」を使います。
- 繰り返しをオンにすると、バナーは自動的に「確認するまで残す」扱いになります。

### 全般タブ

```
ホットキー   区画を選ぶ   [Ctrl + Alt + R]     登録済み
            監視の切り替え [Ctrl + Alt + W]     登録できません(他のアプリが使用中)
☑ ホットキー・トレイから選んだらすぐ監視を始める
☐ 点滅を抑える
☑ 発表中・全画面アプリの使用中は控えめに知らせる
☑ 画面共有に映さない
設定ファイル  C:\Tools\Monitoaster\monitoaster.json      保存できません(書き込み不可)
Monitoaster 0.1.0 ・ MIT License   [ライセンス表示]
```

- ホットキー欄はOS標準のホットキー入力コントロールを使います。登録の成否を欄の右に常に出します。
- 設定ファイルの場所と、保存できるかどうかを常に出します。
- 「ライセンス表示」は、同じタブ内の読み取り専用テキスト欄に依存クレートのライセンスを出します(ダイアログを開きません)。

### 状態欄

ウィンドウ下端の1行です。`状態 ・ 補足` の形にします。直近の出来事やエラーは補足に出し、次の出来事で上書きします。長く続く不具合(ホットキーが登録できない、設定を保存できない)は、全般タブの該当欄の横にも出し続けます。

## 7. 検知の瞬間

### 順番

検知から0.1秒以内に次の4つを同時に始めます。

1. 音
2. 画面演出(全モニター)
3. バナー
4. トレイ通知

### バナー

```
▌ ジョブ完了
▌ 14:32:10 に検知 ・ 所要 12分34秒 ・ 本日3回目
```

- 位置は、カーソルがあるモニターの上部中央です(利用者が見ている画面)。上から36pxの位置に0.15秒で滑り込みます。
- どこをクリックしても閉じて確認済みになります。クリックを受け取りますが、フォーカスは奪いません。
- 「確認するまで残す」がオフなら7秒で消えます。カーソルを載せている間は消えません。消えても状態は検知済み(未確認)のままで、トレイが金色の星になっています。
- 所要時間は `45秒` / `12分34秒` / `1時間05分` の3形式です。`本日N回目` は2回目から出します。
- 「演出を試す」のバナーは `ジョブ完了(試し)` と出し、所要時間と回数は出しません。

### 控えめな知らせ方

「発表中・全画面アプリの使用中は控えめに知らせる」がオンで、OSがその状態だと判定したときは、画面演出と音を出さず、バナーとトレイ通知だけにします。状態は検知済み(未確認)に入るので、あとでトレイを見れば分かります。状態欄には `14:32 に検知 ・ 全画面アプリの使用中のため控えめに通知` と出します。

「演出を試す」は利用者が自分で頼んだ操作なので、この判定にかかわらず演出します(「点滅を抑える」には従います)。

### 繰り返し

確認するまで、設定した間隔で画面演出と音を繰り返します。回を追うごとに強さを一段上げ、「全力」で頭打ちにします。バナーは最初の1枚を残し、作り直しません。

## 8. 中断と復帰

見張りが成り立たなくなったら、誤検知するより先に一時停止します。直ったら、できるだけ利用者の手を借りずに再開します。

| 出来事 | 動き | 再開 |
|---|---|---|
| 画面ロック、スリープ、リモートデスクトップの切断 | 取り込みを休む。基準は保つ | 復帰の2秒後に自動で再開。ディスプレイ構成と対象ウィンドウの位置が変わっていなければ基準を保ち、ロック中の変化を検知する。変わっていれば下の行の扱い |
| 対象ウィンドウの最小化 | 即座に一時停止。基準は保つ | 元の位置に復元されたら自動で再開 |
| 対象ウィンドウの移動(大きさは同じ) | 動いている間は判定を休む | 1秒止まったら、区画を同じだけずらして自動で再開。基準は保つ |
| 対象ウィンドウの大きさ変更、別の拡大率のモニターへの移動 | 一時停止 | 手動(区画を選び直すか、「再開」で今の位置のまま続ける) |
| 対象ウィンドウの終了 | 一時停止 | 手動 |
| ディスプレイ構成の変更 | 一時停止 | 手動 |
| 取り込みの失敗が3回続く | 一時停止 | 手動 |
| 保存された区画が画面の外にある(起動時) | 待機のまま。開始できない | 区画を選び直す |

- 一時停止に入ったら、トレイアイコンをすぐ変えます。5秒たっても続いていたらトレイ通知を1件出します(ウィンドウを掴んで少し動かしただけで通知が出ないように)。
- 自動で再開したときは、枠を1秒見せるだけで通知は出しません。
- 手動の「再開」は基準を取り直します。
- 「動きが止まったら」は、自動再開のとき直前のコマだけ取り直します(動きを見たかどうかは保ちます)。
- 別のウィンドウが区画に重なった場合は、v1では変化として検知します(spec.md 3章の注意のとおり)。

## 9. 自動調整

「今の状態を実行中として測る」を押すと5秒測り、押したボタンの下に結果を1行出します。ダイアログは開きません。

```
[測定中 … 3]
ゆらぎの最大 0.8% → しきい値 2.1% を提案   [適用]
```

実行中の値が、きっかけの条件に引っかからないようにするのが目的です。きっかけによって見るものが違います。

| きっかけ | 測るもの | 提案 |
|---|---|---|
| 変化したら | 測定開始時の画像との差の最大値 | しきい値 = 最大値 × 2 + 0.5ポイント |
| 指定色が現れたら | 指定色の面積の最大値 | しきい値 = 最大値 × 2 + 0.5ポイント |
| 指定色が消えたら | 指定色の面積の最小値 | しきい値 = 最小値 ÷ 2(下限0.1%)。最小値が0なら「指定色が見つかりません」 |
| 動きが止まったら | コマ間の差(0を除く)の最小値と、差が0だった時間の最長 | しきい値 = 最小値 ÷ 2(下限0.1%)、継続時間 = 最長の静止 × 2 + 1秒。一度も動かなければ「動きが見つかりません」 |

「動きが止まったら」は、進捗バーがしばらく止まってから進むような場面で誤検知します。直すべき値は面積ではなく継続時間なので、両方を提案します。

## 10. 時間の決まり

| 項目 | 値 |
|---|---|
| 区画の枠の表示(選択後、「区画を表示」) | 2秒 |
| 開始・停止・再開の枠と札 | 1秒(選択直後は2秒) |
| フォーカスを戻してから基準を取るまで | 0.3秒 |
| ロック・スリープ復帰後の待ち | 2秒 |
| ウィンドウ移動後、再開までの静止 | 1秒 |
| 一時停止のトレイ通知までの猶予 | 5秒 |
| 検知から演出開始まで | 0.1秒以内 |
| バナーの滑り込み | 0.15秒 |
| バナーの自動消去 | 7秒(カーソルを載せている間は止める) |
| 演出の最長 | 8秒 |
| 演出後、判定を再開するまで | 演出終了 + 0.5秒 |
| 繰り返しの間隔 | 既定30秒、10〜600秒 |
| 自動調整の測定 | 5秒 |
| メーターの最大値の線 | 直近10秒 |

## 11. 文言

文言は1つのモジュールに集約します(spec.md 6章)。ここに挙げたものを初期値とします。体言止めか「〜できません」「〜してください」の短い文にし、句点は付けません。

### きっかけの説明

| きっかけ | 説明 |
|---|---|
| 変化したら | 監視を始めたときの見た目と比べ、違う部分の面積で判定 |
| 動きが止まったら | 直前と比べ、一度動いたあと動きが止まり続けたら検知(スピナーや進捗バー向き) |
| 指定色が現れたら | 指定色に近い部分の面積で判定。プレビューをクリックすると色を拾える |
| 指定色が消えたら | 指定色がいったん現れたあと、消え続けたら検知 |

### 状態欄

| 場面 | 文言 |
|---|---|
| 待機、区画なし | `待機 ・ 区画が未指定` |
| 待機 | `待機 ・ 区画 220 × 48 px` |
| 監視中 | `監視中 ・ 12分34秒経過` |
| 検知済み | `14:32:10 に検知 ・ 所要 12分34秒` |
| 検知済み(ロック中) | `14:32:10 に検知 ・ ロック中に変化` |
| 一時停止 | `一時停止 ・ 対象のウィンドウが最小化されています` / `…動きました` / `…閉じられました` / `…ディスプレイの構成が変わりました` / `…画面を取り込めません` |
| 区画が画面外 | `区画が画面の外にあります ・ 選び直してください` |
| ホットキー | `ホットキー Ctrl+Alt+R を登録できません(他のアプリが使用中)` |
| 設定の保存 | `設定を保存できません(フォルダーに書き込めません) ・ このまま使えます` |
| 設定の読み込み | `設定ファイルを読めないため既定値で起動しました` |
| WAV | `WAVファイルを使えません(5MBを超えています)` / `(ネットワーク上の場所は指定できません)` / `(WAV形式ではありません)` |
| 描画の失敗 | `画面演出を使えない環境のため、バナー・音・通知で知らせます` |

### 枠の札

`監視を開始 ・ 変化したら` / `監視を停止` / `監視を再開` / `再開できません ・ ウィンドウが見つかりません`

### トレイ通知

| 場面 | 題 | 本文 |
|---|---|---|
| 検知 | バナーの文言 | `14:32:10 に検知 ・ 所要 12分34秒` |
| 一時停止 | `監視を一時停止しました` | 状態欄の理由と同じ |
| 最初にウィンドウを隠したとき | `Monitoaster` | `トレイに常駐しています。終了はトレイのメニューから` |

## 12. キーボードと表示

- すべてのコントロールに Tab で到達でき、ラベルにアクセスキー(Alt+文字)を付けます。主ボタンは Enter、ウィンドウを隠すのは Esc です。
- 状態は色だけで伝えません。メーターは数値を、トレイは形を、必ず併記します。
- ハイコントラストでは、自前描画の部分(プレビューの枠、メーター)にシステム色を使います。
- v1はライトテーマだけです。コモンコントロールのダークモード対応はしません(手間に対して得るものが小さいため)。
- 表示言語は日本語です。フォントはシステムのメッセージフォントを使います。

### 技術検証(M0)に足す項目

この設計が成り立つかどうかを左右するため、M0の検証に次の2つを足します。

- 画面ロック中のBitBltが何を返すか(失敗か、黒か、ロック前の絵か)。ロックと解除の通知を受け取れるか。P1の前提です。
- フォーカスを奪わない設定のウィンドウ(バナー)が、クリックを受け取れ、クリックされても前面のアプリのフォーカスが変わらないか。P10の前提です。
